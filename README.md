# dsh-reasoning-sync

[English](README.en.md) | 简体中文

把模型端点公布的推理能力，同步进 DSH profile 的模型配置 —— 让模型选择器里的等级跟着端点走，
而不是靠手写 `cordis.patch.yml` 并且随端点漂移。

打开「设置 → 模型」，OpenRouter 卡片里直接显示**端点公布的等级**与**当前等级声明**的差异
（两侧都列出来，还有端点默认落到哪一档），点一下就对齐。

它**只做这一个页面上的事**：不进模型的工具集，也不会在对话里替你改配置——同步是一次配置
维护，差在哪里该由人看着决定（见 `docs/adr/0006`）。

## 它补的是哪一段

DSH 内置的「获取可用模型」把候选元数据削平到 `id` / `name` / `contextWindow` / `maxTokens` /
`inputModalities`：端点上公布的推理能力到不了配置里。而推理等级是**每个模型自己**的能力，
没有等级声明，选择器里就没有等级可选。

本插件**不接管**那条发现流程 —— 同一个 settings 命名空间只允许注册一份发现实现，外部插件
顶不进去 —— 而是**另开一条同步通道**：读端点目录，算出每个模型该有的等级声明，写进配置。

它同步的是**已声明**模型的能力；发现流程管的是**采纳候选**。两者不冲突，上游修好后这个插件
仍然有用。

## 装进 profile

用 Plugin Manager 的 `install_bundle`，target 是这个包的绝对目录。它会替你写 profile 的
`package.json` 与 bundle 选择，**不要**手改 profile 的 `package.json` 或 `cordis.patch.yml`，
也不要在 profile 目录里跑 pnpm。

装好后 profile 里多一条 `reasoning-sync` 行，来自本包自带的 `cordis.patch.yml`。

## 怎么用

### 设置页面里的卡片

「设置 → 模型」里，本插件服务的路由（`baseURL` 指向 `openrouter.ai` 的路由）卡片内会出现一块
面板：

- 打开即预览，**每个已声明模型都占一行**：一致的写「已是最新 · 它现有的等级」，
  有差异的写「当前 X → 端点 Y」，端点没公布能力的、目录里没有的、档位不认识的各自点名；
  整条路由没有差异时标题就是「已是最新：与端点公布的等级一致」；
- 有差异时按「同步到配置」写入，然后自动重读一次，让「已是最新」来自 Host 的回答而不是乐观；
- 失败带原因显示（缺凭据、端点 401/500、非 JSON、revision 冲突、配置不可写），
  失败时**一个字段都不写**。

### 选择器里那个「Default」是什么

模型菜单里除了同步出来的那几档，还有一档 **Default**（locale 键 `effort.providerDefault`）。
它**不属于** `reasoningEfforts`，也不是同步写进去的：那是「提供方默认」，选它等于不给等级
指令，适配器一个 `reasoning` 字段都不发，由端点按自己的 `default_effort` 决定——卡片里
「默认 medium」那个 medium 就是它的落点。

**它落在哪一档，就是端点的 `default_effort`**——卡片每一行末尾那个「默认 medium / high」
报的就是它（端点没公布时不显示）。

它一直都在，因为本插件不写「提供方默认」、也不写路由级默认等级（story 29 / 30）。想让它
消失只能去写路由级 `reasoning`（会改整条路由所有模型的默认行为）或写 `off`（对 mandatory
模型直接 400）——两条都不是这个插件会走的路。

顺带一提：`default` 不是 `supported_efforts` 里的档位名，所以 `reasoningEfforts` 里也没有
`default` 这个键——写了会被适配器的 schema 拒（实测：键集合只有那 7 个名字）。「默认」在
配置里的表达方式就是不选。

## 能做 / 不能做

能做：

- 只在 **已声明** 的模型上，只写 `reasoningEfforts` 一个字段；`name`、`contextWindow`、
  `maxTokens`、`input`、`compat` 等一律不动，模型行不重建、不增删、不重排；
- 端点加了档位就加上，撤了档位就移除；
- 端点没公布能力的模型判**未知**，保持原样（未知不等于非推理）；
- 配置里有、端点目录里查不到的模型（cloaked，例如 `stealth/*`）保持原样，并在报告里点名；
- 端点明确公布"没有可声明等级"时判**非推理**，写 `reasoningEfforts: false`；
- 端点公布了本适配器**不认识**的档位时报告出来，不猜映射、也不因此删掉已有等级；
- 端点说某模型 `mandatory`（推理关不掉）时，该模型上已声明的 `off` 会被移除并在报告里点名
  ——留着它正是那个 400 的成因（ADR-0005）。端点没有这么说时，`off` 原样保留。

不能做：

- **改不了「获取可用模型」按钮返回的候选内容。** 那几处字段白名单在 DSH 应用内部，
  只有上游修复才能让"发现即带上能力"成立；
- **绝不写 `off` 键**，包括 valueless 的 `off:` —— 对 mandatory 模型那会直接 400。
  已存在的 `off` 声明在无关编辑中保持原样，插件既不新增也不删除它；
- 不写路由级默认等级（`providers.<route>.reasoning`），不写「提供方默认」；
- 不自动同步：每次同步都由用户或 agent 显式触发。

## 已知限制与风险

- **卡片只出现在 `openrouter.ai` 的路由上。** 映射规则是 OpenRouter 的
  `reasoning.supported_efforts`；别的端点说的是另一套词汇，插件不猜。其余 provider 卡片
  完全不受影响。想让别的端点也进这条路，改 `lib/routes.js` 的 `CATALOG_HOSTS` 之前先确认它
  的目录形状。
- **路由列表在页面加载时读一次。** 新加一条 OpenRouter 路由后刷新页面，卡片才会出现；
  已经出现的卡片不受影响（每次操作都会重新读配置）。
- **写入会落在 profile 的 `cordis.patch.yml`，也就是设置界面共用的那个文件。**
  已在真实 profile 上验证（离线复现步骤见 `docs/adr/0004`）：被写入那一行的 `config` 块**内部的注释会消失**，
  文件其他部分——文件头注释、其他行、键顺序、缩进——逐字节保留。所以请把说明写在
  **行的上方**或仓库文档里，不要写在 `providers:` 下面。插件自己写出的字段是精确落位的。
- 需要该路由的凭据可用（读 profile 的 `apiKeyEnv`，经 credentials 服务，回退启动环境变量）。
  读不到就明确报「没有凭据」，不写任何东西。
- 写入按 revision 校验：配置被别处改过时拒绝写入并提示重跑，不会覆盖别人的改动。

## 跑测试

```bash
npm test
```

七个套件、86 项，全是确定性的：计划函数穷举映射规则、Host 操作对着注入的 doubles、routes、
apply 与卡片接线、client bundle 在 vm 里加载并驱动渲染与动作、包声明与 profile 接线。

`test/registration.test.mjs` 是唯一会读仓库外东西的套件：它从**真实安装的 DSH 应用**里取出
Models 设置页的座位声明、slot 注册表与端点段语法，用它们验证本插件的座位注册与两条路由。
没装应用时它响亮地 SKIP 并 exit 0。
