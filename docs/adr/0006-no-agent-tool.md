# ADR-0006：撤销 agent 工具，同步只由设置页触发

## 状态

已采纳（2026-10-07）

## 背景

spec issue #1 要求把同步操作也暴露成 agent 工具：

> 21. 我想让这个操作也能通过对话让 agent 执行，**这样我不必非得点界面**。
> 22. 我想让 agent 调用和界面按钮产生**完全一样的结果**，这样两条路径不会各说各话。

Implementation Decisions §2 也随之写了「暴露为 agent 工具，参数与语义跟 UI 动作一致」。

第一版照此实现：`lib/tool.js` 注册 `reasoning_sync`（`preview` 只读、`apply` 写入），它调
`lib/sync.js` 的同一个 `run()`，所以 story 22 是**结构性**成立的——不是靠约定，而是只有一份
实现。

实现落地之后用户否决了这一条，理由是：这个操作**与 agent 本身的业务无关**。它是用户对自己
配置的维护：有它所属的页面，有要读差异的人，也有要按下确认的人。

## 决定

删掉 agent 工具。同步只由「设置 → 模型」的卡片触发。

理由：

- **它买到的比它花掉的少。** 注册的工具会进入每一次请求的模型可见 schema，换来的只是一句
  "不必打开设置页"的触发方式——而那个页面本来就有入口。
- **写配置是人的判断。** 卡片把「当前 X → 端点 Y」摆出来给人看，再由人按下那一下。给模型一个
  能自己改配置的工具，等于把这一步的确认权交给一次未必被要求的调用。
- **它是唯一还没在真实环境跑过的路径。** 与其为一条不需要、又未验证的通路维持 schema 契约
  测试，不如拿掉它，把验证力集中在真正在用的那条上。
- **缓解办法不可用**：`deferLoading`（延迟加载工具 schema）能让成本变小，但
  `dsh-llm-pi-ai` 对任何 `deferLoading: true` 的工具直接抛 `UNSUPPORTED_CONTENT`
  （`dsh-llm-pi-ai/lib/index.js:1230`），而本插件服务的路由都走 pi-ai 适配器。

## 后果

- `lib/tool.js` 与 `test/tool.test.mjs` 删除；`lib/index.js` 只剩两条 Connection Fetch 路由，
  整个 Host 半边挂在一个 effect 上。
- story 22 不再是需要保证的性质——只有一条路径，也就没有两条路径会各说各话。
- `test/registration.test.mjs` 不再校验工具 schema（那个契约没有对象了），它继续校验座位声明、
  座位 key 与两条路由的端点段语法。
- **代价**：想在对话里问一句"现在有没有漂移"不再可能；要查就得打开「设置 → 模型」。
- 如果以后又要工具，它应当调同一个 `run()`，并且重新评估 `deferLoading` 在目标适配器上的支持，
  而不是直接照搬这一版。
